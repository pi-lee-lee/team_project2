4쪽 프로젝트 배경 보강안

기존 두 칸(반복 운반 / 전달 오류)을 아래 현장 문제 3가지로 바꾸고, 오른쪽 결론 문구 위에 도입 효과 수치를 한 줄 넣는 안입니다.

문제 1. 사람이 걸어 다니는 시간이 가장 크다

  • 작업자가 카트를 밀고 넓은 센터를 돌아다니며 물건을 담음. 한 주문의 물건이 여러 구역에 흩어져 있어 동선이 길다. (용마로지스 이천센터, 연면적 1.2만 평)
  • "직원들이 오더 피킹을 하러 수레를 끌고 수시로 왔다갔다했다" (참물류 대표, 이데일리)

문제 2. 잘못 집고, 숙련자에게 의존한다

  • 종이 주문서를 보고 물건을 확인해야 하고, 숙련도에 따라 효율 차이가 크다. 숙련 인력 확보도 어렵다. (용마로지스)
  • 트위니는 상품명·수량을 로봇 화면에 띄워 피킹 오류를 최대 90% 줄인다고 밝힘 (회사 발표, 헬로티)

문제 3. 일할 사람이 없다

  • "일감은 늘어나는데 일할 사람은 구하기 어려운 상황" (참물류 대표, 이데일리)

결론 문구 (오른쪽 초록 글씨 자리)

"물건은 로봇이 옮기고, 사람은 확인만 한다."

그런데 그 확인도 아직 사람이 바코드를 찍고 눈으로 봅니다. 우리는 이 확인을 카메라(YOLO)로 자동화합니다.

5쪽 프로젝트 목표 보강안

세 칸(주문 / 이동·확인 / 통합 운영) 아래에, 4쪽 문제를 우리 기능으로 어떻게 푸는지 대응표로 보여 주는 안입니다. 마지막 줄(확인 자동화)이 트위니 사례와 다른 우리 차별점입니다.

현장 문제 (트위니 사례)우리 프로젝트의 해결근거 기능
주문 정보를 종이로 확인웹 주문 → 서버가 작업 자동 생성Django 주문·작업 관리 (현장의 WMS 연동에 해당)

사람·장애물이 많은 통로바닥 마커 없이 주행, 움직이는 사람 예측 회피LiDAR 지도·위치 추정 + Frenet

(선택) 시장·기술 동향 슬라이드

4쪽 앞에 한 장을 더 넣는다면, "왜 지금 물류로봇인가"를 아래 세 줄로 보여 줍니다.

  • 물류로봇은 산업용 로봇 다음가는 핵심 시장으로, 10년 안에 약 65조 원 규모가 될 것으로 본다. (한국경제 2026.08.05)
  • 기존 AGV는 바닥에 QR 마커·레일을 깔아야 해 공사 기간과 설비 비용 부담이 크다. 트위니는 3D 라이다만으로 인프라 공사 없이 평균 2주 안팎에 도입한다. (한국경제, 이데일리)
  • 우리 로봇도 바닥 표시 없이 LiDAR 지도로 주행하므로 같은 방향이다.

발표 흐름 연결

서론의 문제 3가지를 본론·결과 슬라이드에서 다시 불러주면 발표가 하나의 이야기로 이어집니다.

  1. 문제 (4쪽): 걸어 다니는 시간 / 잘못 집기 / 인력난
  2. 해결 (5쪽 대응표 → 11~14쪽 시나리오): 주문 → A*·Frenet 이동 → YOLO 개수 확인 → 수령 후 복귀
  3. 검증 (15쪽): 문제마다 결과 숫자를 짝지어 보여 줌
    • 걸어 다니는 시간 → 주행 목표 도착 7/7
    • 사람·장애물 많은 통로 → 약 0.45 m 통로 통과, 사람 앞 1초 미만 정지
    • 잘못 집기 → YOLO 개수가 다르면 다음 단계로 넘어가지 않음

확인할 점: YOLO 개수 판정 정확도는 아직 15쪽에 숫자가 없습니다. 테스트 횟수·일치율을 넣으면 차별점이 더 단단해집니다.
